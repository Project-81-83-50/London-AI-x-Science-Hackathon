## KQ1: Machine-readable lab protocol languages and standards — type systems, unit checking, static validation, simulators, and maintenance status

### Takeaway
There are ~12 serious machine-readable protocol formalisms spanning 2010–2026, but almost all the pre-2024 ones are dormant or abandoned, and only two families (Opentrons and PyLabRobot) are actively developed. Genuine *static* checking is rare: Opentrons offers simulation/visualization, XDL has a real compiler with hardware-graph checking, LabOP has ontology-derived type/cardinality validation, and the brand-new BPL has full compile-time dimensional analysis. Unit-aware type systems in lab protocol languages are a 2026 phenomenon (BPL, LAP), not a 2020 one.

### Cited Findings

**LabOP (formerly PAML; SBOL/Bioprotocols Working Group) — effectively dormant since October 2024**
- LabOP is "a free and open protocol representation building on a foundation of UML, Autoprotocol, Aquarium, SBOL RDF, and the Provenance Ontology", implemented as an RDF knowledge representation plus a Python library, and "supports execution as manual 'paper protocols,' by Autoprotocol or by Opentrons" — [LabOP docs](https://bioprotocols.github.io/labop/); [GitHub Bioprotocols/labop](https://github.com/Bioprotocols/labop)
- Peer-reviewed description: Bartley et al., "Building an Open Representation for Biological Protocols", *ACM Journal on Emerging Technologies in Computing Systems* (JETC) 2023 — [DOI 10.1145/3604568](https://dx.doi.org/10.1145/3604568); [author PDF](https://jakebeal.github.io/Publications/JETC23-LabOP.pdf)
- Validation features present: a `Document` can be validated; the OWL ontology "specifies the Python classes, their attributes, their types, and their cardinality"; there is an `ExecutionEngine` that interprets protocols through `BehaviorSpecialization` objects; plus a Markdown converter — [GitHub Bioprotocols/labop](https://github.com/Bioprotocols/labop)
- **Status as of Oct 2026: 51 stars, 911 commits, MIT license, last push 2024-10-07** — i.e. roughly two years without a commit. The separate specification repo has not been pushed since **2023-01-16** — [GitHub API, Bioprotocols/labop](https://github.com/Bioprotocols/labop); [GitHub Bioprotocols/labop-specification](https://github.com/Bioprotocols/labop-specification)
- Independent characterization of LabOP's weakness: it "grounded protocol semantics in RDF/OWL ontologies linked to SBOL, achieving FAIR-compliant provenance at an authoring complexity prohibitive for most bench scientists" — [Song et al. 2026, bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)

**Autoprotocol (Transcriptic → Strateos) — dormant**
- "Autoprotocol is a JSON-formatted data structure developed by Strateos that provides a precise way of describing biological protocols", originally developed at Transcriptic "as a way to define experiments that could be run over the internet on remote robotic automation" — [autoprotocol.org](http://autoprotocol.org/); [Strateos dev docs](https://developers.strateos.com/docs/autoprotocol)
- **Status: `autoprotocol/autoprotocol-python` 125 stars, last push 2023-08-20; `strateos/transcriptic` CLI 49 stars, last push 2024-01-05** — both dormant — [autoprotocol-python](https://github.com/autoprotocol/autoprotocol-python); [strateos/transcriptic](https://github.com/strateos/transcriptic)
- Key expressiveness limitation: Autoprotocol "serialized protocols as parameterised JSON for cloud laboratories but forbids branching logic, precluding conditional workflows" — [Song et al. 2026](https://doi.org/10.64898/2026.05.05.720956)

**Aquarium (Klavins lab, University of Washington) — low but non-zero activity**
- "Aquarium is a web-based application that integrates experimental design, inventory management, protocol execution, and data collection", open-source under MIT, with the AWL and Krill languages for building executable protocols — [Aquarium paper, *Synthetic Biology* 6(1) ysab006, 2021](https://academic.oup.com/synbio/article/6/1/ysab006/6124325)
- Trident is Aquarium's Python API, "a common interface for other applications and scripts to interact with Aquarium" — [Trident/pydent docs](https://aquariumbio.github.io/pydent/)
- **Status: `aquariumbio/aquarium` 68 stars, MIT, last push 2025-12-20** — [GitHub aquariumbio/aquarium](https://github.com/aquariumbio/aquarium)

**BioCoder — abandoned**
- BioCoder "encoded protocols as C++ library calls, achieving unambiguous syntax at the cost of expressiveness beyond simple linear workflows (Ananthanarayanan & Thies, 2010)" — [Song et al. 2026](https://doi.org/10.64898/2026.05.05.720956)
- Only surviving code I could find is a third-party mirror, `nmz787/BioCoder`, 1 star, **last push 2018-09-11** — [GitHub nmz787/BioCoder](https://github.com/nmz787/BioCoder)

**Antha (Synthace) — proprietary; language not open**
- Antha "offered high-level experiment design with automatic reagent computation but imposed proprietary vendor lock-in (Synthace, 2015; Miles & Lee, 2018)" — [Song et al. 2026](https://doi.org/10.64898/2026.05.05.720956)
- Synthace itself is still an operating company selling an automated Design-of-Experiments platform — [Synthace on SelectScience](https://www.selectscience.net/company/synthace); [Antha entry on bio.dev](https://bio.dev/tools/antha-synthace)

**Roboliq — abandoned**
- `ellis/roboliq`, "software for controlling liquid handling robots", 11 stars, **last push 2018-06-19** — [GitHub ellis/roboliq](https://github.com/ellis/roboliq)

**Opentrons Protocol API + JSON protocol schema — very actively maintained, and the main place real pre-run static/dynamic checking exists**
- `Opentrons/opentrons`, Apache-2.0, 520 stars, **last push 2026-10-01 (today)** — [GitHub Opentrons/opentrons](https://github.com/Opentrons/opentrons)
- In March 2026 Opentrons shipped **Protocol Visualization** for the Flex: "a new simulation and visualization capability that allows scientists to simulate and inspect robotic protocols in a dynamic virtual environment before running them", exposing pipette movements, liquid handling actions, labware positions and module status, and letting users step through each action before it runs; it is explicitly framed as "an inspection layer … between AI-generated experimental plans and robotic execution" — [Opentrons news](https://opentrons.com/archives/news/opentrons-viz-ai-lab-workflows); [The Robot Report](https://www.therobotreport.com/opentrons-introduces-dynamic-simulation-visualization-ai-generated-lab-workflows/); [Automation World](https://www.automationworld.com/design/news/55366439/opentrons-flex-gets-protocol-visualization-tool-to-simulate-robotic-lab-workflows-before-execution)
- Simulation/visualization covers protocols authored via OpentronsAI, the Python Protocol API, and Protocol Designer — [Opentrons news](https://opentrons.com/archives/news/opentrons-viz-ai-lab-workflows)

**PyLabRobot — very actively maintained**
- "interactive & hardware agnostic SDK for lab automation", MIT, 554 stars, **last push 2026-10-01 (today)**; supports Hamilton STAR/Vantage, Tecan Freedom EVO, Opentrons OT-2 — [GitHub PyLabRobot/pylabrobot](https://github.com/PyLabRobot/pylabrobot)
- PyLabRobot deliberately does **not** target the Opentrons JSON protocol schema — it generates its own step sequence "to maintain control over simulation steps and which schema the Opentrons expects" — [PyLabRobot forums](https://discuss.pylabrobot.org/t/plr-ot/146)

**XDL / chemputation (Cronin group) — real compiler; hosted on GitLab, light recent activity**
- "XDL is a chemical description language for representing chemical procedures in a machine and human-readable way"; the ChemPU's procedure files use χDL, which "is hardware independent and therefore represents a universal chemical coding format", with the explicit goal that "chemical procedures can be compiled to run on different platforms, similar to computer code being written once and compiled to different processor architectures" — [Chemputation and the Standardization of Chemical Informatics, *JACS Au* 2021, PMC8549037](https://pmc.ncbi.nlm.nih.gov/articles/PMC8549037/)
- Canonical repo: [gitlab.com/croningroup/chemputer/xdl](https://gitlab.com/croningroup/chemputer/xdl); standard docs at www.xdl-standard.com; "XDL will be open source and free to use, like the HTML used on webpages" — [Mehr et al. 2020, Glasgow ePrints](https://eprints.gla.ac.uk/221626/1/221626.pdf)
- A GitHub fork exists (`mcrav/xdl`, MIT, 4 stars, last push **2025-03-28**) — [GitHub mcrav/xdl](https://github.com/mcrav/xdl). No GitHub repo at `croningroup/xdl` (404 via API), so GitLab remains authoritative.

**SiLA 2 — niche**
- "SiLA 2 reached v1.0 in 2019 and v1.1 in 2022, but remains niche in adoption with most instruments still shipping without native support" — [Labcritics, "Lab Automation Lacks a Common Language"](https://labcritics.com/lab-automation-lacks-a-common-language-and-its-holding-science-back/)
- Tecan publishes a royalty-free open-source SiLA 2 SDK — [Tecan SiLA2 SDK, *SLAS Technology*](https://www.sciencedirect.com/science/article/pii/S2472630323000444); [SiLA standard FAQ](https://sila-standard.com/faq/)

**Allotrope — gaining ground in 2026**
- Allotrope's ASM "is gaining momentum in 2026, with USP endorsement achieved in 2026", and Benchling open-sourced an ASM converter library — [Labcritics](https://labcritics.com/lab-automation-lacks-a-common-language-and-its-holding-science-back/)
- Note: Allotrope/ASM is a *data capture* standard, not a protocol execution language.

**Emerald Cloud Lab Symbolic Lab Language (SLL)**
- ECL open-sourced SLL for research use in **August 2023**, "to further support the mission of open science by removing access barriers" — [PRNewswire, Aug 2023](https://www.prnewswire.com/news-releases/emerald-cloud-lab-makes-programming-language-for-conducting-remote-scientific-experiments-open-source-301906218.html); [CIO Influence](https://cioinfluence.com/cloud/emerald-cloud-lab-makes-programming-language-for-conducting-remote-scientific-experiments-open-source/)

**protocols.io — structured but not typed**
- protocols.io exposes a RESTful API returning JSON with OAuth 2.0 auth — [protocols.io for Developers](https://www.protocols.io/developers)
- A third-party package `protocolsio_schemas` "provides a collection of schemas that model all objects available in the Protocols.io v3 API, with a jsonschema validator object" — [GitHub ethanwillis/protocolsio_schemas](https://github.com/ethanwillis/protocolsio_schemas). This is JSON-Schema shape validation only — no units, no state tracking.

**LAP: Agent-to-Instrument Protocol (June 2026) — new, unit-typed, spec-only**
- Zhu, Gao, Chen, Zhu, Huang, "LAP: An Agent-to-Instrument Protocol for Autonomous Science", arXiv:2606.03755, 2 June 2026 — [arXiv](https://arxiv.org/html/2606.03755)
- LAP adds four physical-world primitives on top of A2A/MCP transports: **InstrumentCard** (signed capability description extending W3C WoT Thing Descriptions with safety classifications and physical limits), **exclusive reservation** leasing, a **safety-fence handshake** with parameter-hash-bound operator tokens across safety classes S0–S3, and **MeasurementResult** with "mandatory QUDT/UCUM units, calibration references, and uncertainty propagation" — [arXiv 2606.03755](https://arxiv.org/html/2606.03755)
- It mandates schema **and physical-limits checking before task submission** (rejecting with `ParamOutOfPhysicalLimit`) and mandates rejection if instrument calibration has lapsed; JSON Schema 2020-12 for types — [arXiv 2606.03755](https://arxiv.org/html/2606.03755)
- Explicitly layered *above* SiLA 2, Allotrope/AnIML and OPC-UA LADS rather than competing with them; status is "LAP v0.1 … no normative or implemented status yet", no repo link — [arXiv 2606.03755](https://arxiv.org/html/2606.03755)

### Inferences
- The "standards graveyard" pattern is striking: BioCoder (2018), Roboliq (2018), Autoprotocol-Python (2023), LabOP spec (2023), LabOP library (2024) are all dormant, while the two living projects (Opentrons, PyLabRobot) are *vendor/hardware SDKs rather than interchange formalisms*. For a hackathon, building on Opentrons' Python API + simulator is far lower-risk than building on LabOP.
- LabOP is the best "reuse rather than rebuild" candidate for an IR with provenance semantics (it already embeds PROV-O and has an OWL-derived type system with cardinality checks), but the team must budget for a dormant codebase and prohibitive authoring complexity, which is exactly the criticism levelled at it in the 2026 literature.
- Unit/dimension typing in protocol languages is a 2026 development, appearing independently in BPL (compile-time dimensional analysis) and LAP (mandatory QUDT/UCUM). This means "units in the IR" is now table stakes rather than a differentiator, but it also means the ecosystem has not converged — there is no dominant unit-typed protocol IR to adopt.

### Gaps
- I could not establish LabOP's *intent* going forward (e.g. whether the Bioprotocols Working Group has formally sunset it or merely paused). There is no deprecation notice in the repo. The two-year commit gap is suggestive but not conclusive — someone should ask on the bioprotocols.org mailing list.
- I did not verify whether Opentrons' `opentrons_simulate` CLI performs unit/dimension checking as opposed to deck-collision and labware-existence checking. This matters for scoping and should be checked directly in the Opentrons docs.
- I found no primary source confirming Strateos' corporate fate (see KQ5).

## KQ2: LLMs that generate protocols, benchmarks, and — critically — systems that already put a formal checker in a feedback loop with an LLM

### Takeaway
The "LLM generator + deterministic checker + repair loop" pattern is **not novel and is now crowded**. It was introduced for chemistry in CLAIRify (2023) and, in 2026 alone, at least five independent groups published biology/wet-lab versions: BPL-COGEN (Bota Biosciences, May 2026), ProtoPilot (June 2026), the KIMM dual-agent framework (June 2026), AEGIS (Argonne, July 2026) and ProtoAct (August 2026). BPL-COGEN in particular is a near-exact match for the hackathon concept, including a provenance/trust layer.

### Cited Findings

#### ★ CLOSEST PRIOR ART: BPL / BPL-COGEN (Bota Biosciences, bioRxiv, 7 May 2026)
- Song R.\*, Fu Y.\*, Zhao Z., Yu J., Yuan Q., Chen C.-T.\*\* (\*equal contribution; \*\*corresponding, charlie.chen@bota.bio), "Towards autonomous biology: Compiler-Verified Protocols as a Foundation for Real-World AI Execution", bioRxiv, posted **7 May 2026**, CC-BY-NC 4.0, 24 pages. Affiliations: Bota Biosciences, Hangzhou, China and Lafayette, CA, USA — [bioRxiv DOI 10.64898/2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956); [full PDF](https://www.biorxiv.org/content/10.64898/2026.05.05.720956v1.full.pdf)
- **The thesis is literally the hackathon's thesis:** biology protocols rely on "ambiguous natural-language descriptions: a medium other engineering disciplines abandoned decades ago in favor of compiler verified specification languages", with Verilog/VHDL and typed programming languages named as the models to imitate — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **BPL = Biology Protocol Language**, a DSL with "a biology-native type system in which every quantity carries physical units, every reagent declares its physical form, and every container maintains compiler-tracked state, so that implicit assumptions must be stated explicitly and physically impossible operations are rejected at compile time" — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **BPL's six layers** (from Fig. 1a caption): (1) source = declaration section + numbered protocol blocks, grammar specified in **463 lines of Lark PEG notation**; (2) biology-native type system with compile-time dimensional analysis across **12 base dimensions and ~40 laboratory units**, "rejecting physically impossible operations (e.g., adding a volume to a mass) before execution"; (3) **fourteen high-level laboratory intents** (transfer, incubate, run_pcr, …) with typed named arguments; (4) a **container state engine** tracking current volume, concentration, contents and maximum capacity per vessel, "rejecting programs that would overflow a container or draw from an empty source"; (5) a **three-tier trust model (Declared, Calibrated, Verified)** that "tracks the provenance and confidence of every state value, supporting Research, GLP and GMP (21 CFR Part 11) compliance contexts"; (6) control flow with conditionals, iteration, parallel blocks and structured error recovery — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
  - *Note a minor internal inconsistency in the paper itself:* Fig. 1a says "12 base dimensions", Fig. 1c and the Results text say "nine base physical dimensions". Flag this if citing the number.
- **BPL-COGEN pipeline:** five stages — input normalization and resource grounding (against a local lab catalogue with bilingual alias matching), grammar-constrained code generation by **BPL-Nano-30B** (a fine-tuned 30-billion-parameter model), **three-gate compiler validation**, diagnostic-guided repair, and deterministic artefact production — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **The three gates:** the *parse gate* verifies grammar conformance and produces a typed AST; the *semantic gate* checks "unit consistency, type safety, state coherence, and identifier resolution"; the *plan gate* performs intent lowering to a DAG of execution primitives plus dependency-aware scheduling and backend capability checking. "Each gate emits typed diagnostics with error codes, source locations, and targeted repair hints." Failures are fed back as "contextualized repair prompts", with a **maximum of three repair attempts** — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **Five deterministic output artefacts:** validated BPL source as canonical form; execution-plan DAG with resolved volumes, well addresses and dependency edges; a diagnostic report with volume-tracking and unit-conversion **audit trails**; a workflow graph for visual verification; and a per-step state trace recording container volume, concentration and **trust-level transitions** — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **Engineering scale (relevant to hackathon feasibility):** language and compiler "iteratively refined through 14 revision cycles, validated against 150 published protocols, and supported by 1,175 test cases spanning dimensional analysis, state tracking, intent lowering, and error recovery" — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **Results:** benchmark of **300 published *Nature Protocols* papers**, 10 BPL variants generated per protocol, 2,992 valid variants after filtering; scored by a general-purpose LLM judge on experiment match, protocol validity and phase completeness; **overall fidelity 95.1 ± 8.3%**; **98.6% compilation success rate within two iterative** repair attempts — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **Wet-lab validation:** GFP expression library construction compiled to two execution contexts (manual and liquid-handler-assisted) with reproducible outcomes; and an HPLC→UHPLC method translation for five fat-soluble compounds, where compiler-calculated parameters (flow 0.613 mL/min, injection 0.42 µL, gradient 2.18 min) closely matched adopted values, giving a 14.7-fold run-time reduction and 95.8% solvent reduction — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **Errors vs warnings distinction** (directly relevant to a checker's UX design): the compliance engine issued four *warnings* (plate-ratio deviation beyond the 25% pharmacopoeial equivalence limit, packing-type change, pore-size change, 5.1× backpressure increase) rather than errors, "by design: errors indicate physically invalid operations; warnings flag methodological changes that alter the analytical basis and require informed human judgement"; the analyst's acceptance of each was recorded in the audit trail — [bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)
- **No code release found.** I searched the full 24-page text for "availab", "github", "open source", "license", "code is" and found no code- or data-availability statement and no repository URL. Bota Biosciences is a company; treat BPL/BPL-COGEN as **closed-source prior art**. This is the single most important opening for the hackathon team.

#### CLAIRify (2023) — the original verifier-in-the-loop system, now abandoned
- Yoshikawa, Skreta, Darvish, et al., "Errors are Useful Prompts: Instruction Guided Task Programming with Verifier-Assisted Iterative Prompting", arXiv:2303.14100 (March 2023) — [arXiv PDF](https://arxiv.org/pdf/2303.14100); project page [ac-rad.github.io/clairify](https://ac-rad.github.io/clairify/)
- Journal version: "Large language models for chemistry robotics", *Autonomous Robots* (2023) — [Springer, DOI 10.1007/s10514-023-10136-2](https://link.springer.com/article/10.1007/s10514-023-10136-2)
- Mechanism: "CLAIRify generates XDL with an automated iterative prompting between a generator and a verifier", using GPT-3.5 to translate natural language to XDL, then "automatically verifies its syntax and structure, identifies any errors, appends those errors to the prompt, and prompts the LLM again" until valid. The verifier is explicitly **rule-based** and checks "syntax correctness and environment constraints" — allowed actions, tags, parameters, bracket balance — [CLAIRify project page](https://ac-rad.github.io/clairify/); [UofT CS news](https://web.cs.toronto.edu/news-events/news/cs-researchers-design-clairify-framework-to-improve-chemistry-robotics-planning)
- Reported results: 97–100% success in generating valid experimental plans; solubility measurement error 7.2–12.3% — [CLAIRify project page](https://ac-rad.github.io/clairify/)
- **Status: `ac-rad/clairify` has 0 stars, no license, last push 2023-10-27 — abandoned.** — [GitHub ac-rad/clairify](https://github.com/ac-rad/clairify)
- **How far it went vs. the hackathon idea:** CLAIRify's verifier is a syntax + allowed-action + environment-constraint checker over XDL. It does *not* do dimensional analysis, container-state tracking, resource feasibility, or provenance. It is single-agent (one generator), not multi-agent. So CLAIRify establishes the *loop* but not the *depth of the checker*.

#### Other 2026 verifier-in-the-loop protocol systems
- **ProtoPilot** — Jiang, Tang, Sun, Tang, Hou, Han, Wang, Yang, Liang, Wang, Lou, Wang, Bai, Yang, "A Self-Evolving Agentic System for Automated Generation and Execution of Biological Protocols", arXiv:2606.31763 (v1 30 June 2026, v2 2 July 2026). "A self-evolving multi-agent system" maintaining alignment between biological intent, quantitative procedures, device constraints and experimental feedback; evaluated on "294 synthetic-biology and molecular-biology tasks derived from 98 gold-standard protocols" with expert rubrics and **device-level validation gates**; 90.2% expert preference and **88.24% pass rate on Opentrons platforms vs 32.35% for an OpentronsAI baseline**. Verification is layer-wise + device-level gates + wet-lab testing; no code release mentioned — [arXiv:2606.31763](https://arxiv.org/abs/2606.31763)
- **KIMM dual-agent framework** — Choi H., Kim J.Y., Lim H.\*, Jeon S.\* (Korea Institute of Machinery & Materials), "Dual-Agent Framework for Cross-Model Verified Translation of Natural-Language Protocols into Robotic Laboratory Platform", arXiv:2606.20120, June 2026. A **Parser Agent** formalizes the NL protocol into a structured representation; **a rule-based mapping engine deterministically incorporates the robot platform's operational constraints** to generate device-level commands; a **heterogeneous LLM Validation Agent** checks completeness, parameter accuracy and execution order and "triggers a self-correction loop with structured feedback when errors are detected". Evaluated with a 7 Parser × 3 Validator sweep on ELISA protocols; accuracy–latency compared against LLM end-to-end direct mapping; demonstrated end-to-end on a Bradford protein-quantification assay — [arXiv:2606.20120](https://arxiv.org/abs/2606.20120)
- **AEGIS** — Setty P.V., Ramanathan A., Foster I., Stevens R., "AEGIS: Assay-Aware Protocol Validation and Runtime Monitoring for Open-Source Liquid Handling Robots", arXiv:2607.15620, submitted 17 July 2026. Targets protocols that are "syntactically valid but violate assay-specific invariants", with the canonical example "tip reuse between a PCR template and a no-template control". Layer 1 is pre-flight checking that "pairs a curated machine-readable assay rule database with an LLM that reasons over OT-2 Python code", reaching **adjusted F1 of 0.97**, and "a free open-weight model ties the best proprietary one". Works directly on OT-2 Python (no IR). **AEGIS is open source** and is claimed as "the first system to unify pre-flight assay-aware validation with runtime visual monitoring for an open-source liquid handler" — [arXiv:2607.15620](https://arxiv.org/abs/2607.15620)
- **ProtoAct** — Liu Z., Gu J., Du Z., Wang Z., Jin H., Lu Q., Wang Q., Xiao T., Pan M., Zhou D., "ProtoAct: Turning Wet-Lab Protocols into Embodied Robotic Actions", arXiv:2608.01690, 3 August 2026. "A structured protocol-grounding framework that converts free-form biological procedures into state-aware, embodiment-ready action sequences": **ProtoRAG** for retrieval, **RefineChecker** to identify and correct incomplete or contradictory steps, and **ActSchema** to convert procedures into constrained JSON function sequences. Dataset **BioP2E**: 22 manually annotated cell-culture protocols, 258 monitoring conditions, 910 executable subtasks, 962 grounded action calls; evaluated across seven LLMs. No code release mentioned — [arXiv:2608.01690](https://arxiv.org/abs/2608.01690)

#### Benchmarks
- **BioPlanner / BIOPROT** — O'Donoghue et al., "BioPlanner: Automatic Evaluation of LLMs on Protocol Planning in Biology", EMNLP 2023 — [arXiv:2310.10632](https://arxiv.org/pdf/2310.10632); [ACL Anthology 2023.emnlp-main.162](https://aclanthology.org/2023.emnlp-main.162/). BIOPROT is "a dataset of 100 high-quality biology protocols sourced from Protocols.io", filtered from over 9,000 entries for biology-centricity, reproducibility and ≥3 distinct steps. Method: an LLM converts NL protocol → pseudocode; then a model must reconstruct the pseudocode from a high-level description plus admissible pseudocode functions; a teacher model generates admissible pseudofunctions and gold pseudocode to grade a student. Externally validated by generating novel protocols from retrieved pseudocode, one of which "was run successfully in a biological laboratory" — [ACL Anthology](https://aclanthology.org/2023.emnlp-main.162/)
- **BioProBench** — Liu, Lv, et al., "BioProBench: Comprehensive Dataset and Benchmark in Biological Protocol Understanding and Reasoning", **ICML 2026**. Built on 27K (26,933) original protocols, yielding **556,171 structured instances** across five task families: Protocol QA, Step Ordering, Error Correction, Protocol Generation, Protocol Reasoning. Finding: "leading LLMs have systemic weaknesses in handling causal logic, quantitative precision, and structured generation"; ten LLMs "score well on basic comprehension and poorly wherever exact numbers, causal ordering, safety, or complete step sequences matter". A RAG approach, **ProAgent**, raises protocol QA accuracy from ~70% to 85% and step recall from 42.8% to 62.24% — [arXiv:2505.07889](https://arxiv.org/html/2505.07889); [GitHub YuyangSunshine/bioprobench](https://github.com/YuyangSunshine/bioprobench) (72 stars, last push **2026-07-21**); [HF dataset](https://huggingface.co/datasets/GreatCaptainNemo/BioProBench)
- **LAB-Bench / ProtocolQA (FutureHouse)** — announced 16 July 2024; 2,457 questions across 8 broad categories and 30 subtasks. **ProtocolQA** specifically "evaluate[s] models' ability to troubleshoot commonly published lab protocols, with questions that introduce errors in protocols and ask for how to fix the procedure" — [FutureHouse announcement](https://www.futurehouse.org/research-announcements/lab-bench-measuring-capabilities-of-language-models-for-biology-research); [HF futurehouse/lab-bench](https://huggingface.co/datasets/futurehouse/lab-bench)

### Inferences
- BPL-COGEN is the benchmark the hackathon will be measured against. Its reported numbers (95.1% fidelity on 300 *Nature Protocols* papers, 98.6% compile success within two repairs) and its engineering scale (1,175 compiler test cases, 14 revision cycles, a 30B fine-tune) are not reachable in a hackathon — so the team's claim must be about *architecture differences* (open source, a proof-assistant-grade checker, literature-linked provenance) rather than about matching performance.
- The 2026 cluster shows **convergent evolution**: five independent groups arrived at "separate generation from verification" in ~four months. That is strong evidence the idea is correct, and equally strong evidence it is not novel. The honest framing is "we are implementing the emerging consensus architecture, with a differentiated checker".
- There is a real, exploitable split in how 2026 systems do verification: BPL-COGEN and the KIMM framework use **deterministic** checkers; AEGIS and ProtoAct use **LLM-based** checkers (AEGIS explicitly pairs a rule DB *with* an LLM reasoning over code; ProtoAct's RefineChecker is a model). - All benchmark evidence (BioProBench, LAB-Bench ProtocolQA) agrees that LLMs fail specifically at *quantitative precision, causal ordering, safety and complete step sequences* — which is precisely the failure class a deterministic unit/state checker catches. This is the strongest available motivation for the project and should be cited as such.

## KQ3: AI-scientist / lab-agent systems — plan verification, provenance tracking, static safety checking vs. trusting the LLM

### Takeaway
Essentially none of the flagship AI-scientist systems have static plan verification; their "verification" is either LLM self-critique (Google co-scientist's Reflection agent), tool-mediated lookups (ChemCrow's controlled-substance screening), or physical experiment as the oracle. A rigorous 2026 survey quantifies this: **no LLM-era system in its corpus demonstrates an externally validated in-loop oracle.**

### Cited Findings

**The quantitative case that verification is the gap**
- Ding T., Nannapaneni A., Liu B., Zhang L., "Autonomous Research Agents: A Survey of AI Scientists and the Verification Gap", arXiv:2608.05179v1 [cs.CY], dated 29 June 2026 (announced August 2026), 119 pages — [arXiv:2608.05179](https://arxiv.org/pdf/2608.05179)
- Corpus: screened 125 candidates → 35 included works → 26 full-text coded (24 runnable systems + 2 study/position works) on seven audit dimensions (lifecycle stage, autonomy level, evaluation method, released artifacts, human-in-the-loop points, novelty-verification method, result-selection disclosure) — [arXiv:2608.05179](https://arxiv.org/pdf/2608.05179)

## KQ4: Formal methods applied to chemistry/biology/lab procedures — does "Lean for chemistry/biology" exist, and does Mathlib/SciLean do dimensional analysis?

### Takeaway
Lean *is* being used for chemistry, but exclusively to formalize **theory and calculation pipelines** (thermodynamics, adsorption isotherms, dimensional analysis, BET surface areas) — all from a single group, Josephson's AtomsLab at UMBC. **No one has used Lean, or any proof assistant, to check wet-lab protocols.** Dimensional analysis in Lean exists as a standalone 2025 project, not as part of Mathlib; I found no evidence of units support in SciLean's core. SMT-based static checking of liquid-handling-adjacent programs does exist, but only for digital microfluidic biochips, from a 2014–2022 line of work.

### Cited Findings

**LeanChemicalTheories — Lean 3, dormant**
- Bobbin, Josephson et al., "Formalizing chemical physics using the Lean theorem prover", *Digital Discovery* 3(2), 264 (2024) — [RSC, DOI 10.1039/D3DD00077J](https://pubs.rsc.org/en/content/articlehtml/2024/dd/d3dd00077j); [article landing page](https://pubs.rsc.org/dd/article/3/2/264/804885/Formalizing-chemical-physics-using-the-Lean); [author PDF](https://atomslab.github.io/static/pdf/publications/bobbin_2023.pdf)
- The project "demonstrates how the mathematics of theories in chemical physics can be written in the language of the Lean theorem prover", with formalizations including Langmuir adsorption, BET adsorption and thermodynamic laws; proofs hosted on a semi-interactive site at [atomslab.github.io/LeanChemicalTheories](https://atomslab.github.io/LeanChemicalTheories/)
- **Status: `atomslab/LeanChemicalTheories` 44 stars, no license file, last push 2024-03-12.** It was written for **Lean 3**, which is deprecated; the paper itself notes "Lean 3 is now deprecated; future proofs are recommended to be written in Lean 4" — [GitHub atomslab/LeanChemicalTheories](https://github.com/atomslab/LeanChemicalTheories); [RSC article](https://pubs.rsc.org/en/content/articlehtml/2024/dd/d3dd00077j)
- **Mark LeanChemicalTheories as effectively abandoned** (Lean 3, 2.5 years without a commit), superseded by the two projects below.

**Dimensional analysis in Lean 4 — exists, standalone, not in Mathlib**
- Bobbin M.P., Jones C., Velkey J., Josephson T.R., "Formalizing dimensional analysis using the Lean theorem prover", arXiv:2509.13142 [physics.chem-ph], submitted **16 September 2025** — [arXiv HTML](https://arxiv.org/html/2509.13142v1); [author PDF](https://atomslab.github.io/static/pdf/publications/bobbin_2025.pdf)
- What is formalized: physical dimensions as "mappings from base dimensions to exponents", with a proof that they "form an Abelian group under multiplication"; derived dimensions and dimensional-homogeneity theorems; physical variables combining a numeric value with a dimension; SI base units and fundamental constants; and the **Buckingham Pi theorem**. Case study: the Lennard-Jones potential, where the framework "enforces dimensional consistency and enables formal proofs of physical properties such as zero-energy separation and the force law" — [arXiv:2509.13142](https://arxiv.org/html/2509.13142v1)
- The work builds **on top of** Mathlib (version 4.23.0-rc1), with the authors noting "Mathlib has developed almost all of the mathematical analysis needed for scientific analysis of values" so their focus is dimensional analysis specifically — [arXiv:2509.13142](https://arxiv.org/html/2509.13142v1)
- **Status: `atomslab/LeanDimensionalAnalysis`, "Formally-verified dimensional analysis in Lean", 5 stars, last push 2025-09-12** — a research artifact, not a maintained library — [GitHub atomslab/LeanDimensionalAnalysis](https://github.com/atomslab/LeanDimensionalAnalysis)

**Λs (lambda-s) — a units-of-measure *type system* mechanized in Lean 4**
- `ericeallen/lambda-s`: "A calculus of units of measure with conversion, mechanized in Lean 4" — "a typed lambda calculus in Lean 4 where conversion between units of the same dimension is primitive, with a full mechanization including statics, dynamics, denotational semantics, and the Pi theorem of dimensional analysis" — Apache-2.0, **last push 2026-10-01 (today)**, but **0 stars** — [GitHub ericeallen/lambda-s](https://github.com/ericeallen/lambda-s)
- This is the closest existing thing to "a formally specified units-of-measure type system a protocol IR could be typed against", and it is actively being written right now. Very early / single-author.

**LeanBET — Lean 4, 2026, formally verified *calculation pipeline***
- Ugwuanyi E.D., Jones C.T., Velkey J., Josephson T.R., "LeanBET: Formally-verified surface area calculations in Lean", arXiv:2605.16169, submitted **15 May 2026** — [arXiv](https://arxiv.org/abs/2605.16169); [PDF](https://arxiv.org/pdf/2605.16169)
- Formalizes the BET method in **Lean 4**, verifying window enumeration (soundness and completeness), monotonicity checks and knee selection, linear regression (proving "the regression coefficients returned by the algorithm agree with their specification-level definitions"), the BET linearized expression derivation, and floating-point arithmetic correctness tied to real-number proofs. Agreement with the BETSI Python reference "to machine precision for 18 of the 19 isotherms", 0.03% deviation on UiO-66 — [arXiv:2605.16169](https://arxiv.org/abs/2605.16169)
- **Status: `atomslab/LeanBET` 6 stars, last push 2026-05-21** — [GitHub atomslab/LeanBET](https://github.com/atomslab/LeanBET)
- **This is the most important precedent for the hackathon's framing**: it shows the pattern "take a lab-relevant computation, specify it in Lean 4, prove the implementation matches the spec, validate against the Python reference." It is about *data analysis*, not *protocol execution* — which leaves the protocol side open.

**SciLean**
- `lecopivo/SciLean`, "Scientific computing in Lean 4", 530 stars, **last push 2026-02-18** — actively developed — [GitHub lecopivo/SciLean](https://github.com/lecopivo/SciLean)
- I found **no evidence of dimensional-analysis or units support in SciLean's core**. The only units-related item in the SciLean orbit is a third-party extension repo, `alok/scilean-extra`, described as "SciLean extensions: Egyptian fractions, Lisp compiler, units", 1 star, last push 2026-01-02 — [GitHub alok/scilean-extra](https://github.com/alok/scilean-extra)

**Mathlib**
- The 2025 Lean dimensional-analysis paper's framing — that it contributes dimensional analysis *because* Mathlib already supplies the analysis but not the dimensions — is the strongest available evidence that **Mathlib itself has no dimensional-analysis / units-of-measure support** — [arXiv:2509.13142](https://arxiv.org/html/2509.13142v1). **SMT / model checking of liquid-handling-adjacent programs — exists, but only for digital microfluidics**
- Bhattacharjee S., Banerjee A., Chakrabarty K., Bhattacharya B.B., "A Framework for Automated Correctness Checking of Biochemical Protocol Realizations on Digital Microfluidic Biochips", arXiv:2211.04719 — [arXiv abs](https://arxiv.org/abs/2211.04719); [PDF](https://arxiv.org/pdf/2211.04719)

- Earlier conference version: "Correctness Checking of Bio-chemical Protocol Realizations on a Digital Microfluidic Biochip" (2014) — [IEEE 6733183](https://ieeexplore.ieee.org/document/6733183/)
- Related: "A framework for end-to-end verification for digital microfluidics", *Innovations in Systems and Software Engineering* (2021) — [Springer DOI 10.1007/s11334-021-00398-3](https://link.springer.com/article/10.1007/s11334-021-00398-3); and "A Framework for Translation and Validation of Digital Microfluidic Protocols" (2021) — [Springer chapter](https://link.springer.com/chapter/10.1007/978-981-16-4294-4_9)

**Does anything literally called "Lean for chemistry/biology" exist?**
- The AtomsLab projects (LeanChemicalTheories, LeanDimensionalAnalysis, LeanBET) are the closest, and they are "Lean for chemical *theory* and *calculation*", not "Lean for lab *procedures*" — [atomslab.github.io/LeanChemicalTheories](https://atomslab.github.io/LeanChemicalTheories/); [arXiv:2605.16169](https://arxiv.org/abs/2605.16169)

### Inferences
- **"Lean for biochem" is an unoccupied name but a half-occupied space.** The dimensional-analysis half is done (twice, in Lean 4). The protocol-checking half is done, but in bespoke compilers (BPL) and SMT (microfluidics), never in a proof assistant. A genuinely novel contribution would be *typing a protocol IR against a Lean 4 units/dimension formalization* — but note this is engineering novelty, not scientific novelty, and the team should be honest that a bespoke compiler (BPL's approach) gets 95% of the practical benefit at 5% of the cost.

- The microfluidics SMT line is the right citation for "formal methods have been applied to liquid-handling programs before" and shows the field has had Z3-based checkers for over a decade — so "SMT checking of lab programs" is definitively not novel.

Useful as evidence that commercial LLM protocol generation without a strong checker fails most of the time.
- **Synthace**: an operating company selling automated Design-of-Experiments; the Antha language is characterized in the literature as offering "automatic reagent computation but imposed proprietary vendor lock-in" — [Song et al. 2026](https://doi.org/10.64898/2026.05.05.720956); [Synthace profile](https://www.selectscience.net/company/synthace); [Chemistry World webinar](https://www.chemistryworld.com/webinars/synthace-accelerating-process-development-with-automated-design-of-experiments/4012170.article)

### Inferences
- The commercial state of the art is **simulation**, not **static verification**. Simulation catches collisions, missing labware and timing; it does not catch "this buffer concentration is dimensionally inconsistent with the stated dilution" or "this control shares a tip with the template". AEGIS's whole premise — protocols that are "syntactically valid but violate assay-specific invariants" — is the proof that the commercial layer leaves a real gap. This is the cleanest honest gap statement available to the hackathon team.
- Nobody commercial ships unit/dimension checking on protocols. BPL is research-stage and closed. So the *product* space is genuinely open even though the *research* space is crowded.

## KQ6: Novelty assessment — what is genuinely new in (multi-agent planning + formal protocol IR + deterministic checker + per-claim provenance labels)

### Takeaway
Three of the four components are prior art, and the *combination of the first three* was published in May 2026 (BPL-COGEN) with a trust/provenance layer attached. The only defensible novelty is narrow: an **open-source** implementation, a **proof-assistant-grade** rather than bespoke checker, and **per-claim literature provenance attached to protocol parameters** (as opposed to BPL's calibration-state trust tiers). The team should lead with "we are implementing and opening up the emerging consensus architecture, with a differentiated provenance model", not with "nobody has done this".

### Cited Findings — what is NOT novel (must be positioned honestly)

1. **LLM → structured protocol IR → deterministic checker → repair loop.** Established in chemistry by CLAIRify in March 2023 ([arXiv:2303.14100](https://arxiv.org/pdf/2303.14100)) and in biology by BPL-COGEN in May 2026 ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)), with three further 2026 instances: the KIMM dual-agent framework ([arXiv:2606.20120](https://arxiv.org/abs/2606.20120)), ProtoPilot ([arXiv:2606.31763](https://arxiv.org/abs/2606.31763)), and ProtoAct ([arXiv:2608.01690](https://arxiv.org/abs/2608.01690)).
2. **Compile-time unit and dimension checking in a lab protocol DSL.** BPL has it across ~9–12 base dimensions and ~40 units, explicitly "rejecting physically impossible operations (e.g., adding a volume to a mass) before execution" ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)); LAP mandates QUDT/UCUM units on every numeric parameter and result plus physical-limits rejection ([arXiv:2606.03755](https://arxiv.org/html/2606.03755)).
3. **Container-state tracking with overflow/depletion rejection.** BPL layer 4 does exactly this ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)).
4. **Multi-agent LLM planning of experiments.** Coscientist ([*Nature* 624, 2023](https://www.nature.com/articles/s41586-023-06792-0)), ChemCrow ([*Nature MI* 2024](https://www.nature.com/articles/s42256-024-00832-8.pdf)), CRISPR-GPT ([*Nature BME* 10(2), 2026](https://www.nature.com/articles/s41551-025-01463-z)), Biomni ([bioRxiv 2025](https://www.biorxiv.org/content/10.1101/2025.05.30.656746v1)), Google co-scientist ([Google Research](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/)), ProtoPilot ([arXiv:2606.31763](https://arxiv.org/abs/2606.31763)).
5. **Provenance / trust labels on protocol values.** BPL's layer 5 is "a three-tier trust model (Declared, Calibrated, Verified)" that "tracks the provenance and confidence of every state value, supporting Research, GLP and GMP (21 CFR Part 11) compliance contexts", with per-step trust-level transition traces and audit trails ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)). LabOP builds on the Provenance Ontology (PROV-O) ([LabOP docs](https://bioprotocols.github.io/labop/)). PaperQA2 does per-claim citation binding ([GitHub](https://github.com/Future-House/paper-qa)).
6. **Static/formal checking of lab programs.** SMT/Z3 correctness checking of biochemical protocol realizations on digital microfluidic biochips dates to 2014 and was extended through 2022 ([arXiv:2211.04719](https://arxiv.org/abs/2211.04719); [IEEE 6733183](https://ieeexplore.ieee.org/document/6733183/)).
7. **Pre-run inspection of AI-generated protocols as a shipping product.** Opentrons Protocol Visualization, March 2026 ([Opentrons news](https://opentrons.com/archives/news/opentrons-viz-ai-lab-workflows)).
8. **Compiling one protocol source to multiple execution backends (human / robot / simulation).** BPL's intent-lowering layer compiles ~15 intents to ~20 execution primitives targeting human step sheets, liquid handlers or simulation ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)); LabOP exports to paper protocols, Autoprotocol and Opentrons ([LabOP docs](https://bioprotocols.github.io/labop/)); XDL's explicit design goal is write-once-compile-to-many-platforms ([JACS Au 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8549037/)).
9. **The "biology should have what Verilog gave hardware" argument.** Made verbatim in the BPL paper's opening ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)). Not an original framing.
10. **Separating generation from verification across agents.** A survey-level finding: agent systems "structurally separate the processes of generation and verification through the collaboration of models with distinct roles, enabling error detection and correction via cross-verification" — [arXiv:2606.20120](https://arxiv.org/abs/2606.20120).

### Cited Findings — what appears genuinely open (candidate novelty)

1. **No proof assistant has ever been used to check wet-lab protocols.** The three Lean-for-chemistry projects target theory and calculations: chemical physics theorems ([*Digital Discovery* 2024](https://pubs.rsc.org/en/content/articlehtml/2024/dd/d3dd00077j)), dimensional analysis + Buckingham Pi ([arXiv:2509.13142](https://arxiv.org/html/2509.13142v1)), and BET surface-area pipelines ([arXiv:2605.16169](https://arxiv.org/abs/2605.16169)). Searches for Lean + biology protocol formalization in 2026 returned nothing in this space. **"No evidence found" — the strongest form of negative claim I can support.**
2. **No open-source implementation of the full LLM + unit-typed IR + deterministic checker stack.** BPL-COGEN has no code- or data-availability statement and no repo (confirmed by full-text search of the 24-page preprint); CLAIRify's repo is abandoned at 0 stars, no license ([GitHub ac-rad/clairify](https://github.com/ac-rad/clairify)); ProtoPilot and ProtoAct mention no release. AEGIS *is* open source but works on OT-2 Python with no IR and uses an LLM inside its checker ([arXiv:2607.15620](https://arxiv.org/abs/2607.15620)).
3. **Per-claim *literature* provenance attached to protocol parameters.** BPL's trust tiers are about *calibration state* (Declared/Calibrated/Verified), not about which paper a parameter came from ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)). PaperQA2 does per-claim citation but has no protocol IR ([GitHub](https://github.com/Future-House/paper-qa)). LabOP's PROV-O is execution provenance, not source-literature provenance ([LabOP docs](https://bioprotocols.github.io/labop/)). **I found no system that labels each protocol parameter with the source claim it came from and carries that label through a checker.**
4. **A strictly non-LLM checker is the minority position and can be defended.** The 2026 field splits: deterministic checkers in BPL-COGEN and the KIMM mapping engine; LLM-involving checkers in AEGIS (rule DB + LLM over code) and ProtoAct (RefineChecker). The survey evidence that "no LLM-era system … demonstrates an externally validated in-loop oracle" ([arXiv:2608.05179](https://arxiv.org/pdf/2608.05179)) is a direct argument for determinism.

### Inferences — recommended honest positioning
- **Do not claim** novelty on: the architecture, unit checking, state tracking, multi-agent planning, multi-backend compilation, or the Verilog analogy. Each has a 2023–2026 citation above.
- **Do claim**, carefully: (a) an open, reusable artifact where the field has only closed or abandoned ones; (b) a checker whose soundness is itself machine-checked (Lean 4), which no protocol system has; (c) provenance that links protocol parameters to literature claims, which complements rather than duplicates BPL's calibration trust tiers; (d) explicitly zero LLM involvement inside the checker.
- **Cite BPL-COGEN prominently and early.** A reviewer or judge who knows the May 2026 preprint and does not see it cited will discount the whole project. Citing it and differentiating is strictly better.
- **Reuse rather than rebuild:** Opentrons Python API + simulator as the execution backend; AEGIS's open-source assay rule database as a source of invariants; PaperQA2 for citation-bound provenance; `atomslab/LeanDimensionalAnalysis` or `ericeallen/lambda-s` if a Lean-typed units layer is wanted; BioProBench and LAB-Bench ProtocolQA as off-the-shelf evaluation. Do **not** build on LabOP (dormant since Oct 2024) or Autoprotocol (dormant since 2023) unless interchange with legacy systems is a stated goal.
- **Scope realism:** BPL took 14 revision cycles, 150 protocols of validation, 1,175 compiler test cases and a 30B fine-tune ([bioRxiv 2026.05.05.720956](https://doi.org/10.64898/2026.05.05.720956)). A hackathon should deliberately pick a narrow protocol class (the 2026 papers chose ELISA, cell culture, PCR, GFP cloning) and a small intent set.

### Gaps
- Whether BPL/BPL-COGEN has been open-sourced or journal-published since May 2026 (see KQ2 gaps). This single fact could change the novelty calculus substantially and should be checked before any public claim.
- I did not find AEGIS's repo URL, so "AEGIS is open source" is the authors' claim rather than something I verified.
- I did not search ChemRxiv specifically, nor NeurIPS/ICML/ICLR AI-for-science workshop proceedings 2024–2026 directly (my 2026 hits came through general arXiv search). There may be workshop papers on exactly this combination that I missed; a targeted OpenReview search would be a sensible follow-up.
- No source found for whether anyone has attempted PRISM-style probabilistic model checking of *protocols* (as opposed to biological systems). Unresolved.
